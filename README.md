## Проект (предварительно, решаем сегодня в 19:00)
**Кейс 3 «Моделирование полёта и расчёт траекторий». Проект «ДРЕЙФ» — планировщик миссий электрического буксира «СКАУТ» от А-РОКЕТС.** Клиент присылает заявку: какие спутники, с какой орбиты попутного запуска, на какие орбиты и к какому сроку. ДРЕЙФ отвечает, выполнима ли она, какой стратегией, за сколько суток и сколько ксенона уйдёт, и честно говорит, где модель не уверена.

Почему так:
- **Это задача самого партнёра.** А-РОКЕТС продаёт «Перевод МКА на целевые орбиты с различными наклонениями и высотами» и в сравнении с конкурентами ставит показатель «Время маневра, дн» (`work/src/arockets/strings.txt`, `work/FACTS.md`).
- **Задача не учебная.** У буксира тяга 55 мН, и неверная стратегия съедает весь запас. Развести спутники по плоскостям на 15° прямым манёвром стоит около 3,1 км/с, а у буксира с грузом 50 кг есть только 2,0–2,8 км/с. Если использовать естественный дрейф плоскости от сплюснутости Земли (эффект J2), хватает около 0,2 км/с, зато это занимает около 170 суток. Проверка: `python3 work/calc/scout_first_calc.py`, масса буксира не опубликована, взята вилка 100–150 кг.
- **Физика проверена, а реальность медленнее модели.** Наша формула сходится с прямым численным расчётом подъёма 550 → 1000 км лучше чем на 1 % (`python3 -I work/calc/numeric_check.py`). При этом реальные спутники OneWeb поднимались с 450 до 1200 км примерно 100 суток, а та же модель даёт 68–84. Разницу даёт эксплуатация: паузы тяги, тень, зарядка. Её и надо моделировать.
- **Модель дрейфа сходится с реальными спутниками.** У всех 72 спутников OneWeb с двух запусков индийской LVM3 модель по известной истории высоты и наклонения восстановила уход плоскости за 9–14 месяцев с ошибкой меньше 0,3° (медиана 0,14–0,19°). Это проверка эффекта, а не прогноз миссии. Две ступени ракеты, которые сначала попали в выборку, нашёл Антон. Подъём 450 → 1190 км у 26 спутников второго запуска занял медиану 188 суток. Подробно: `work/kaggle/oneweb_drift/RESULTS.md`.

**Что уже опубликовано до нас и как мы это учитываем.** Французская Exotrail продаёт такой софт (ExoOPS, с 2020 года учитывает дрейф плоскости и тень). В 2026 году вышла научная статья Apa, Hudson, Romano про оптимизацию дрейфовых орбит для обслуживания нескольких клиентов малой тягой (`work/research/4_literature.md`, раздел A1). Поэтому новизну метода мы не заявляем. Наш вклад — открытый проверяемый расчёт под конкретный «СКАУТ», сверка с реальными полётами и честный отказ там, где модель не знает.

**Альтернатива — кейс 1 «Машинное зрение в системах управления КА»:** камера буксира оценивает положение и ориентацию спутника при сближении, с честной неопределённостью. Открытый набор данных SPEED+ уже подключён к нашему Kaggle с двумя GPU T4 (проверено 25.10).

## Как запустить расчёты
Нужен только Python 3.
```
python3 work/calc/scout_first_calc.py   # стратегии развоза и бюджет буксира
python3 -I work/calc/numeric_check.py   # численная сверка подъёма орбиты, около 1 с
python3 -I work/calc/strategy_map.py    # карта стратегий: сколько ксенона стоит каждый срок
python3 -I work/calc/price_numeric_check.py   # численная проверка чисел слайда 2, около 30 с
python3 -I work/tools/make_charts.py    # графики для слайдов
python3 -I work/tools/build_deck.py     # сборка слайдов в HTML, с --pdf ещё и PDF через Chrome
```
Задание на Kaggle запускается из `work/kaggle/oneweb_drift/` командой `kaggle kernels push -p .` (нужен свой токен Kaggle и свой ник в поле `id` файла `kernel-metadata.json`).
