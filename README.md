## Проект (предварительно, решаем сегодня в 19:00)
**Кейс 3 «Моделирование полёта и расчёт траекторий». «ДРЕЙФ» — помощник инженера для предварительной оценки миссий электрического буксира; первый рассматриваемый профиль — «СКАУТ» от А-РОКЕТС.** Целевой сценарий: инженер сравнивает рассмотренные стратегии по срокам и ксенону и передаёт проверяемый отчёт на дальнейшую проработку. Сейчас готовы исследовательские расчёты отдельных сценариев; обработка реальных заявок и полноценная доставка нескольких аппаратов ещё требуют разработки и проверки. Участие А-РОКЕТС в пилоте не подтверждено.

Почему так:
- **Это задача самого партнёра.** А-РОКЕТС продаёт «Перевод МКА на целевые орбиты с различными наклонениями и высотами» и в сравнении с конкурентами ставит показатель «Время маневра, дн» (`work/src/arockets/strings.txt`, `work/FACTS.md`).
- **Задача не учебная.** У буксира тяга 55 мН, и неверная стратегия съедает весь запас. Развести спутники по плоскостям на 15° прямым манёвром стоит около 3,1 км/с, а у буксира с грузом 50 кг есть только 2,0–2,8 км/с. Если использовать естественный дрейф плоскости от сплюснутости Земли (эффект J2), хватает около 0,2 км/с, зато это занимает около 170 суток. Проверка: `python3 work/calc/scout_first_calc.py`, масса буксира не опубликована, взята вилка 100–150 кг.
- **Есть численная сверка отдельных сценариев.** Формула сходится с прямым численным расчётом подъёма 550 → 1000 км лучше чем на 1 % (`python3 -I work/calc/numeric_check.py`, сохранённый результат). Это сравнение моделей, а не подтверждение точности настоящего буксира. Причины расхождения расчётных и наблюдаемых сроков нельзя однозначно установить только по истории орбит.
- **Проверена реконструкция дрейфа по истории орбит.** Для 72 спутников OneWeb с двух запусков индийской LVM3 модель использует фактическую историю высоты и наклонения за всё окно и восстанавливает изменение узла. Максимальное расхождение — около 0,29°, медиана абсолютной ошибки в конце окна — 0,14–0,19°. Это проверка отдельного эффекта, не прогноз всей миссии из начального состояния и не проверка расхода топлива. Две ступени исключены; пересчёт сохранённого CSV не заменяет полный повтор обработки TLE. Подробно: [RESULTS.md](work/kaggle/oneweb_drift/RESULTS.md).

**Что уже опубликовано до нас и как мы это учитываем.** Exotrail лицензировал ExoOPS внешним организациям; в 2020 году продукт уже учитывал дрейф плоскости и тень. Текущие условия отдельной продажи не установлены. В 2026 году вышла работа Apa, Hudson, Romano об оптимизации дрейфовых орбит для обслуживания нескольких клиентов малой тягой (`work/research/4_literature.md`, раздел A1). Новизну метода не заявляем. Гипотеза ценности «ДРЕЙФА» — сокращение работы инженера при подготовке предварительного ответа с явными допущениями. Сравнение с текущим процессом клиента пока не проведено.

**Альтернатива — кейс 1 «Машинное зрение в системах управления КА»:** камера буксира оценивает положение и ориентацию спутника при сближении, с честной неопределённостью. Открытый набор данных SPEED+ уже подключён к нашему Kaggle с двумя GPU T4 (проверено 25.10).

## Как запустить расчёты
Нужен только Python 3.
```
python3 work/calc/scout_first_calc.py   # стратегии развоза и бюджет буксира
python3 -I work/calc/numeric_check.py   # численная сверка подъёма орбиты, около 1 с
python3 -I work/calc/strategy_map.py    # карта стратегий: сколько ксенона стоит каждый срок
python3 -I work/calc/price_numeric_check.py   # численная проверка чисел слайда 2, около 30 с
python3 -I work/kaggle/oneweb_drift/summarize_payloads.py   # пересчёт сохранённой выборки OneWeb
python3 -I work/tools/make_charts.py    # старые графики v4; источник и подписи ещё требуют обновления
python3 -I work/tools/build_deck.py     # сборка старых слайдов v4; с --pdf также PDF через Chrome
```
Задание на Kaggle запускается из `work/kaggle/oneweb_drift/` командой `kaggle kernels push -p .` (нужен свой токен Kaggle и свой ник в поле `id` файла `kernel-metadata.json`).
